Goal
----
Determine whether the supplied source code (`source.cpp`) is secure.

What to do
---------
1. Open and read `source.cpp`.  
2. Analyze the code for common security problems such as:
   - Buffer overflows
   - Integer overflow / underflow
   - Use‑after‑free or dangling pointers
   - Unchecked user input
   - Insecure API usage (e.g., strcpy, sprintf)
   - Any other vulnerability relevant to C/C++ code.
3. Decide on the security status:
   - If you find **any** issue, consider the code NOT secure.
   - If no issues are found, consider the code secure.

If the code is **NOT secure**, for each problem record:
- A brief description of the flaw (e.g., “buffer overflow on line 42”).
- How an attacker could exploit it.

If the code is **secure**, simply note that no security issues were identified.

File creation
-------------
* Create a file named `test-2.md` in the folder whose path will be provided to you.
* The markdown file must contain the following sections (exact headings optional, but content required):

  - **What you found?** – summary of any vulnerabilities or a statement that none were found.
  - **How it could be badly used?** – description of potential exploitation (omit if no issues).
  - **Which line(s) of the original source are problematic?** – list of line numbers (or “none”).
  - **Recommendation for a fix** – concise advice on how to remediate each issue (do NOT modify `source.cpp`).
